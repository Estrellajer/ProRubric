# Evaluation

Every reported score is produced by a judge that is not the training reward's
(paper Sec. 5.1): DeepSeek-V4-Pro grades both medical axes and all model-judged
benchmarks; Doubao-lite (same family as the training reward) and GPT-5.6-luna (a
third family) are used only to compare judges. All calls go through
`../reward/judge_client.py`; configure the evaluation judge with

```
RUBRIC_JUDGE_BASE_URL   chat-completions endpoint
RUBRIC_JUDGE_API_KEY    bearer token
RUBRIC_JUDGE_MODEL      model id (required, no default)
RUBRIC_JUDGE_QPM / RUBRIC_JUDGE_TPM / RUBRIC_JUDGE_MAX_CONCURRENCY
```

and the other judges with the `LITE` / `ALT` role variables
(`RUBRIC_JUDGE_ALT_MODEL`, ...). Grading outputs are append-only JSONL keyed so
that re-running skips finished verdicts.

| Path | Paper | What it computes |
|---|---|---|
| `healthbench_judge.py` | coverage g (HealthBench-full) and appropriateness c (HealthBench consensus): Tables 2 and 3, Fig. 2 | one call per criterion with HealthBench's official `GRADER_TEMPLATE`; official score |
| `pairwise.py` | Table 1(a) and `tab:rubric_free_full`, medicine | rubric-free blind pairwise, both orders |
| `pairwise_variants/` | Table 1(a) in science, dialogue, writing; the GPT-5.6-luna column; seeds 43/44; the equal-budget (2,048-token) comparison of Sec. 5.3 and `fig:pairwise_winrates`(b) | see its README |
| `appropriateness_probe/` | `tab:probe`, Fig. 3(c), probe numbers in Sec. 5.4–5.5 | four domain-independent criteria on 200 prompts per domain |
| `official/` | WritingBench, Creative-v3, Arena-Hard v2, ResearchQA columns of Table 2 | upstream scoring protocols with the evaluation judge |
| `harness/` | responses for every table; MedQA and GPQA-Diamond columns of Table 2; Doubao-lite columns of `tab:ablations_full`, `tab:per_seed_ablations`, `tab:seeds` | vLLM generation with the paper's sampling settings; per-record scoring |
| `ghost_share.py` | Sec. 3.1 and the Judges paragraph of App. C: share of physician-consensus criteria the training-family judge marks satisfied and the evaluation judge marks unmet (27.5% before training; 46.2 / 44.3 / 44.1% for seeds 42 / 43 / 44) | positive criteria the training-time judge grants and the evaluation judge denies |

Responses are generated by `harness/generate.py`; `harness/score_records.py` scores
MedQA and GPQA-Diamond (multiple-choice accuracy, no judge) and the second
evaluator's per-criterion HealthBench verdicts (`c_lite`, `g_lite`). The judge-agreement analysis against
physicians (App. B.1) is in `../analysis/hb_metaeval/`; aggregation of per-run scores
into the paper's tables is in `../analysis/tables/`.

## Inputs

- **questions**: a parquet file whose rows carry `prompt` (string or
  `[{"role","content"}]` messages) and `extra_info.rubric`, a list of
  `{"criterion": str, "weight": float}`; row ids come from `extra_info.id` (then
  `sample_id` / `prompt_id`). HealthBench-full and consensus use the public
  HealthBench files converted to this layout (consensus: the physician-written
  criteria; full: the example-specific criteria).
- **responses**: repeatable `NAME=PATH` arguments pointing at JSONL files with one
  object per row: `id`, `response`, and optionally the training-time judge's
  `satisfied` booleans and `score`.

Responses in the paper are generated with Qwen3 in non-thinking mode, up to 8,192
new tokens (2,048 for the equal-budget comparison), temperature 0.7, top-p 0.8,
seed 42.

## `healthbench_judge.py`

Regrades responses with the official HealthBench `GRADER_TEMPLATE` (verbatim from
[openai/simple-evals](https://github.com/openai/simple-evals), MIT license,
`healthbench_eval.py`), one judge call per rubric criterion.

```
python3 healthbench_judge.py run \
    --questions healthbench_consensus.parquet \
    --responses rubric_rl=rubric_rl.jsonl --responses prorubric=prorubric.jsonl \
    --grades grades.jsonl
python3 healthbench_judge.py summarize \
    --questions healthbench_consensus.parquet \
    --responses rubric_rl=rubric_rl.jsonl --responses prorubric=prorubric.jsonl \
    --grades grades.jsonl --out summary.json
```

Scoring is the official HealthBench definition, in one `score()` function: a
criterion's points are awarded iff `criteria_met` is true; the question score is the
achieved points divided by the sum of positive points (negative-weight criteria
subtract when met but never enter the denominator), clipped to [0, 1]; the reported
number is the mean over questions, x100. A per-criterion average instead weights
every criterion equally and inflates the untrained model's score.

`summarize` reports per-method means over the fully graded paired question set, paired
deltas with bootstrap 95% intervals, and criterion-level agreement with the
training-time judge (from the responses files' `satisfied` / `score`). Paired sets
across many methods and seeds (App. B.2) are cut by `../analysis/tables/`.

The paper's c and g columns were graded with the same template, rendering, parser
and score, plus behaviours that decide which items end up fully graded (up to
three attempts per verdict, responses carrying an `error` skipped, grading restricted
to a fixed prompt set, up to three passes over failed criteria, `max_tokens` 3000).
`../analysis/tables/grade_hb.py` implements exactly that and writes the same grades
format; use it to reproduce the tables, and this script for a quick two-method
comparison.

## `pairwise.py`

No rubric is shown to the judge: two responses to the same prompt are presented
anonymously, and the judge picks the more useful one for the user who wrote the
last message (relevance to the actual ask, fit to the user's situation, medical
accuracy and safety, no bloat; length is not a plus). Every pair is judged in both
orders; a win counts only when both orders agree, and ties and inconsistent
decisions are excluded from the win-rate denominator. Questions are hash-sampled.

```
python3 pairwise.py run \
    --questions healthbench_consensus.parquet \
    --responses base=base.jsonl --responses rubric_rl=rubric_rl.jsonl --responses prorubric=prorubric.jsonl \
    --pairs base:rubric_rl,rubric_rl:prorubric,base:prorubric \
    --verdicts verdicts.jsonl
python3 pairwise.py summarize \
    [same --questions/--responses/--pairs] --verdicts verdicts.jsonl \
    --grades grades.jsonl   # optional: sign agreement with the HealthBench per-question scores
```

## `ghost_share.py`

Zero judge calls. Joins `healthbench_judge.py` grades with the responses files'
training-time verdicts and reports, over positive-weight criteria, the share the
training-time judge grants but the evaluation judge denies, with a per-question
bootstrap interval (Sec. 3.1; untrained model vs Rubric-RL, seed 42).

```
python3 ghost_share.py --questions healthbench_consensus.parquet \
    --responses rubric_rl=rubric_rl.jsonl --responses prorubric=prorubric.jsonl \
    --grades grades.jsonl
```

## Dependencies

Python 3.10+, `pyarrow`; `httpx` for pooled connections (the client falls back to
the standard library). `official/` and `../analysis/hb_metaeval/` download pinned
upstream files with their `fetch_*.sh` scripts.
