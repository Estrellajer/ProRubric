# From paper to code

Every table and figure of the paper, and the in-text numbers that do not come from a
table, mapped to the files that produce them. Paths are relative to the package root.

All RL training methods share one entrypoint (`python -m verl.trainer.main_ppo`) and one reward
manager (`reward/rubric_judge.py`; the Graded variant adds `reward/rubric_judge_repeat.py`).
Most methods differ only in the training parquet, so most rows below point at a data
script plus a config.

Judges (configured by environment variables, `reward/judge_client.py`): the training
reward comes from Doubao-mini (`RUBRIC_JUDGE_TRAIN_*`); in-training validation uses
Doubao-lite (`RUBRIC_JUDGE_VAL_*`); every reported score is graded by DeepSeek-V4-Pro
(`RUBRIC_JUDGE_*`, also the dimension generator); Doubao-lite as second evaluator
(`RUBRIC_JUDGE_LITE_*`) and GPT-5.6-luna (`RUBRIC_JUDGE_ALT_*`) are used only to
compare judges.

## Pipeline

| Stage | Files |
|---|---|
| Atomic training / held-out sets | `data/build_medical_split.py` (RubricHub medical + HealthBench validation set), `data/build_domain_split.py` (writing, dialogue), `data/build_science_split.py` (RaR-Science) |
| ProRubric's dimensions | `generate/generate_dimensions.py` (variants `anchored`, `writing`, `dialogue`, `science`, `k1`) → `data/build_prorubric_release.py` |
| Controls and baselines data | `data/build_*.py`, `generate/rewrite_atomic.py` (see `data/README.md`) |
| Training | `configs/*.yaml` and the override-only variants in `configs/README.md`; `reward/`; `distill/` (OPSD); `engine_patches/` (RuscaRL) |
| Responses and second-evaluator scores | `eval/harness/generate.py`, `eval/harness/score_records.py` (MedQA / GPQA-Diamond accuracy; Doubao-lite `c_lite`, `g_lite`) |
| Evaluation-judge grading | `analysis/tables/grade_hb.py` (HealthBench consensus c and full g; `--judge-role ALT` for GPT-5.6-luna), `eval/official/` (WritingBench, Creative-v3, Arena-Hard v2, ResearchQA) |
| Aggregation | `analysis/tables/` (one spec JSON maps methods and seeds to files) |
| Figures | `figures/`, `analysis/training_dynamics/plot_training_dynamics.py` |

## Not in the package

- **The Implicit reward baseline** discussed in the paper is omitted from this
  release package.
- **Model checkpoints, generated responses and judge verdicts.** Not redistributed;
  every script regenerates or re-grades them.
- **The teaser figure (Fig. 1)** is an illustration.
- **The generation harness's scheduler and cluster integration.** `eval/harness/`
  keeps the generation settings and the per-record scoring; job submission,
  checkpoint merging and queueing are infrastructure and not needed to reproduce a
  number.
- **The engine extensions for OPSD** (teacher context and student/teacher union
  support) are described in `distill/README.md` and `distill/upstream/README.md`;
  only the generalized-JSD loss is provided as a patch.
- **The Arena-Hard v2 question parquet** used for generation held 748 of the 750
  upstream questions; `eval/official/README.md` lists the two missing ids.
- **The salt of the 300-prompt draw** for the training-dynamics checkpoints; the ids
  themselves are shipped (`analysis/training_dynamics/healthbench_consensus_300_ids.json`).

## Known small differences

- `analysis/tables/ablations.py`: the live consensus common set can hold one more id
  (3,141) than the paper's 3,140 if late retries complete; the spec's
  `consensus_ids` freezes the set.
